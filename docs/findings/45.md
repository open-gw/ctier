# 45 — what a record sink has to be

Spec **1.19.0**. Requires 44. Independent of 46
and of the engine. C10's requirement sentence
is unaltered. Engine behaviour was not
changed.

35 found the failure: probe, 503, nothing
recorded. The fix shipped in the engine —
records through the gateway log; L1–L2 emit
schema-valid records that way. The
specification did not take it. Six versions
behind. A fix that lands in the engine and
not in the specification is a fix a second
implementation does not get.

---

## Part 1 — the property, not the log

Do not bless the mechanism. A sentence that
only admitted the gateway log would have
been the nine-times mistake: naming what
the reference does instead of what a sink
must provide.

A sink is where the record is written. The
record MUST survive failure of the
component whose behaviour it records. It
MUST be retrievable by someone who was not
present when it was written. Absence of a
record MUST be detectable.

The first clause is 35: a record *to*
custody is worthless when custody failed.
The second is ordinary after-the-fact
audit. The third is uncomfortable. A sink
you cannot audit for gaps lets C10 hold
for every request that was recorded.

Two mechanisms satisfy: a custody ledger,
and the gateway's own structured log. An
implementation MUST state which it relies
on. The next sink is judged against the
property, not against this pair.

The gateway log qualifies because it is
not the component whose failure a
custody-unavailable Attempt records, and
because a later reader can retrieve the
line without having been present at the
write.

No new C-letter. The property belongs to
C10's record.

---

## Part 2 — coverage stays; conduct does not

C10's coverage remains the governed set.
The sink requirement is not that coverage.
It is an obligation on the implementation's
own conduct: every record it writes,
including a refusal of a path outside the
composition.

Same split as 42's C4. Coverage gets
scoped. The obligation on how the
implementation records does not. A bound
to the governed set would permit a
non-qualifying sink for those records.

---

## Part 3 — the trade

L1–L2 emit through the log. L3 has
custody. They are not equivalent. The
ladder exists because they are not.

What the log provides. A schema-valid
Decision or Attempt that survives the
component whose failure it records. A
later reader can retrieve the line.

What it does not. A ledger you can query
for what is missing. Custody's records
are the set; a missing correlation is a
fact. Durability remains requirement 4.
Outcome records remain custody's.

That is a trade, not a caveat. An operator
who has L1 or L2 has classified and
recorded. They have not withheld, and they
have not got a ledger.

---

## Part 4 — evidence

C10-via-gateway-log is Observed. The
runtime suite asserts schema-valid
Decision and Attempt records on the
gateway log of both live engines. 35
built the Attempt path; 37 added the
record assertions.

This is the first Observed evidence in
the specification. The word already
appeared as a kind under C13's none, and
the escalation bound is Derived. No
Observed sample had been recorded.

---

## Whether the property exposed a sink

No currently-used claimed sink fails it.

Apigee's `print()` would fail
retrievable-by-someone-not-present. An
evaluator with a trace running can read
the object; an operator without one
cannot. The ladder already treats that
as artefact-only. Writing the property
confirms the standing.

Recording the 503 to custody, or to
nowhere, would fail the first clause.
That is 35. The engine no longer does
it. Kong's JSONL fallback is custody
ingest, not a third mechanism; the file
would qualify.

---

## Whether absence-detectable made the cut

Yes. The cost is the sentence that keeps
the ladder honest. The log meets that
clause only as far as a collector can be
joined to an independent request stream.
Without it, L1–L2 would read as a
ledger.

---

## The observation this pass earns

The gap stayed open because nothing
checks an engine fix against the
document. Conformance compares
implementations to the specification.
Nothing compares the specification to
what an implementation learned.

35 closed a C10 failure in the place
that runs. The letter that a second
implementation is held to still
described a sink the reference had
already abandoned.

## NEW-MATTER

A step that reads an engine finding
and asks whether the specification
