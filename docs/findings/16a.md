# 16a — the third deployment requirement, and whether precedence was ever stated

Spec **1.6.0**. Task 16 showed fragment mode cannot guarantee the
ingress strip runs before anything reads a header — on Kong, APISIX,
and Apigee, by three different mechanisms. The prediction was "at
least one." All three failed. That is stronger than a third bullet.

## Part 4 first — where precedence was stated

**It was not.** 1.5.0 says no agent-supplied `x-ctier-*` header may
*reach a backend*. C11, as the rest of the project uses it, is an
injected tier: classification ignores a header an agent set, and
unknown `x-ctier-*` names are ignored. Neither document says the
strip must run before any other component *reads* such a header.

A fragment deployment can therefore satisfy the letter of 1.5.0
(the backend never sees the forged name — Kong's request-transformer
at 801 sets `x-ctier-forged`, ctier at 800 strips it) while CORS at
2000 and jwt at 1005 have already seen whatever the agent sent.
That is the emit⊆strip defect one level down: a mechanism (keep it
off the backend) standing in for a property (nothing in the path
acts on an agent-supplied provenance header).

**Not added to C11.** Expanding the criterion from injected-tier to
plugin order is a larger act than a document addition. Same rule
14b applied. Recommendation: a later task, if anyone takes it,
should decide whether C11 is restated as that temporal property or
left as classification-ignores-injection, with the temporal property
living only in `headers.md`. This task put it in `headers.md`.

## Requirement 3

On the deployment list, in those words. Its own sentence: 1 and 2
are satisfied at deployment; 3 must be re-established whenever the
enforcement point's configuration changes. The operational
consequence: SHOULD detect, SHOULD re-run on change; in the
reference that is the conflict report, so regeneration is operating
procedure.

## What 3 does not contradict

Requirements 1 and 2 are topology: who may call the backend, and
that custody is a trusted caller outside the strip. Requirement 3 is
order *inside* the enforcement point's request path. Custody execute
is already exempt from the strip; 3 does not pull it back in.

The shared cadence ("classifications and not the guarantees") is
deliberate, not a collision. Requirement 1's "none of the
guarantees" is broader than 3's "not the forgery protection." A
coexisting proxy can still be a chokepoint and still treat custody
as trusted while C11-as-path-order fails. That is the point of
giving 3 its own sentence rather than a third one-time bullet.

## Evidence

Kong and APISIX fragment mode: 24/24 differential over a populated
proxy, not C11-conformant. Apigee fragment: artefact merge only.
The 352 live figure is not Apigee's.

## The compiled-absence boundary

This project's recurring result is that a guarantee holds because of
a structural fact, not because of a check: exclusion is a scope
never granted, suspension a scope removed, delegation an identity
never entitled. C11 in bundle mode was the same shape — the strip
runs first because nothing else is there to run.

Fragment mode is the first case where the structural fact is not
available and nothing replaces it. Whether that means the
compiled-absence family has a boundary at coexistence, or whether
some other structural fact could do the same work in a shared proxy,
is the most interesting open question the build has produced. It is
not answerable from one task.
