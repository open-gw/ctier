## Part 0 — conformance before adopting

Recorded before the text moved.

Kong `record_decision` runs in
`access()` before headers are set and
before the request is proxied. With
custody, that is POST `/v1/ledger`.
On failure the function returns `nil`
and the request still proceeds.
Without custody it is
`kong.log.notice` of a schema-valid
Decision — the error log, in the
access phase, not the nginx access
log. APISIX does the same in
`serverless-post-function`, phase
`access`, via `_lua_forward_provenance`.
The write is issued before upstream.
It is not a durable record before
the act: ledger failure is fail-open,
and log durability is requirement 4.

The access log is emitted around the
response. That is a different sink.
The C10 sink is `[ctier-decision]`.

1.19.0's absence-detectable clause
already said the log meets that
property only as far as a collector
can be joined to an independent
request stream. That is in view. It
is not reopened. C10's sink
wording is unaltered.

The claimed sink is
`kong.log.notice` of
`[ctier-decision]` — the error
log, not the access log. An
error-log line has no request
sequencing. That path may not
satisfy C10's third sink
clause. 45's unanswered third,
surfaced again. Named in the
1.20.0 version entry. C10 is
not rewritten.

## `X-Delegation-Chain`

Adopted. Header rule, not a letter.
The admission rule's scope is
implementation behaviour that mints
a C-series criterion.

Who may set: the agent. The
enforcement point does not emit it.
An estate component may inject it.

Strip: the enforcement point does
not. The name is outside `x-ctier-*`
and outside the 16c bound
(namespace plus named aliases).
Requiring a strip would have been a
new alias the live targets do not
implement. Not required.

What a backend may believe: nothing.
Provenance, not entitlement. A
backend is outside the trust
boundary. The forbid is a
condition ctier states and does
not enforce. That is the class
of the four deployment
requirements. Numbered there as
requirement 5. The header trust
status points at it. It does
not restate the MUST.

13-series: `standard` is compiled
client entitlement, not token
lineage. This header carries
lineage. The example said the
gateway checks each hop. That is
believing it. Believing it is a
path around the 1.3.0 replacement.
1.3.0 removed the lineage
mechanism; it did not deprecate it.
The name remains. The name is not
a second mechanism. The
enforcement point MUST NOT
classify from it. Scoping that
to `standard` read as if
`constrained` may. Two profiles
exist: `standard` and
`constrained`. `constrained`
puts the entitlement check at
the enforcement point and is
unbuilt. Neither permits
classifying from agent-supplied
lineage. No permit is invented.

Live Kong and APISIX do not read
the header. They classify from
compiled `required_scope`. They
satisfy. The Python classifier
still walks `delegation_chain`.
That is the corpus adapter, not
the live enforcement point. Engine
follow-up, not this edit.

## `X-Incident-Id`

Adopted. Header rule, not a letter.

Who may set: the enforcement point
MAY emit it on a C9 response. The
agent MAY send it inbound.

Strip: inbound, not stripped.
Outside the 16c bound. Not
required.

What a backend may believe: nothing.
It is not the join key. The join
key is `x-ctier-correlation-id`.
C9 forbids a correlation identifier
on this disposition; this header is
not one.

An agent can present any value.
That forges an incident label, not
the decision record. Inbound
`x-ctier-correlation-id` is
stripped and rewritten.

Live targets do not emit it, do
not strip it, and do not believe
it. They satisfy the trust rule.

## C14 — No credential persistence

Admitted. The heading gains a
letter. The body is unaltered.

Admission rule: a second
implementation must not persist an
agent credential. Testable against
a stored pending context. Not a
document rule. Not a deployment
condition the implementation
cannot make unavoidable.

Mechanism or property: property.
Receiving expiry as a value is how
`expiresAt` is computed, not the
criterion.

Scope: the policy service, as
written. Not the enforcement point
alone. Not everything ctier
specifies. The named subject is
the persist path.

Evidence: none. The corpus does
not observe a persisted pending
context.

The reference policy service
strips `Authorization` from
persisted context. It satisfies.

## C15 — Agent suspension is an
authorisation concern

Admitted. The heading gains a
letter. One sentence is added:
this forbids gateway-local
suspension.

Admission rule: a second
implementation must not implement
suspension at the enforcement
point and must not consult the
policy service to ask. Testable.
The authorisation server removing
the scope is the estate. C8
already recorded that half.

Mechanism or property: property.
Compiled-absence — scope removed
at the authorisation server — is
the named mechanism.

Scope: the authorisation layer,
not the enforcement point.

Evidence: none.

Stating it forbids gateway-local
suspension. A denylist, a shared
dictionary of suspended agents, or
a consult of custody for
suspension would not satisfy. That
is in the text deliberately.

The reference never GETs custody
to ask whether an agent is
suspended. It checks
`required_scope`. It keeps no
denylist. It satisfies the
enforcement-point half.

## Recorded before acted on

Rejected. Not adopted. Not
stopped.

The sentence is not in `spec/`.
It lives in engine documents as a
restatement of C10 before 1.1.9.
46 already named it
engine-invented. 11a dropped
"before" because the record is
evidence and MAY be asynchronous.
Re-adopting it would undo that
and contradict C10's current
letter.

Part 0: neither live target
writes a durable record before
the operation proceeds. Adopting
would make both non-conformant.

The requirement is not right.
C10 already states the property.
This is an engine local choice.
It is to come out of engine
documents. This task says so. It
does not edit them. ADR-0005
still quotes the old sentence.
