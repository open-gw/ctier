# 44 — the governed set, defined once

Spec **1.18.0**. Requires 43. Independent of the engine.
No criterion's requirement altered. Engine behaviour
was not changed.

43 listed `governed set` as a concept introduced
in C12 / C10 / C1, untitled. C2, C10, C12 and C1
each name the composed description. 1.17.0 said
C13's composition is the governed set by
definition. This pass compares before it
collapses.

---

## Part 1 — the four sentences

Do not collapse before checking. A mechanical
deduplication that flattens a real distinction
is worse than duplication.

| Criterion | Scope sentence | Same as C12's boundary? |
|---|---|---|
| C1 | C1 applies to the operations ctier governs: those present in the composed description from which the enforcement configuration was generated. A path reachable at the enforcement point but absent from that composition is outside this criterion. | yes — letter for letter except the identifier |
| C2 | Fail-closed is C2: an operation in the composed description with no `x-ctier-*` declaration is Tier 4. That default is not a default for paths outside the composition. | no — sub-case: operations *in* the set lacking assignment, not the criterion boundary |
| C10 | C10 applies to the operations ctier governs: those present in the composed description from which the enforcement configuration was generated. A path reachable at the enforcement point but absent from that composition is outside this criterion. | yes — letter for letter except the identifier |
| C12 | C12 applies to the operations ctier governs: those present in the composed description from which the enforcement configuration was generated. A path reachable at the enforcement point but absent from that composition is outside this criterion. | the reference sentence |
| C13 | The digest is over the composition; that composition is the governed set by definition. | no — different sentence: digest subject, not a criterion-scope paragraph |
| C4 | This criterion is deliberately unbounded. It applies to every decision the implementation takes, including a refuse of a path outside the composed description. | no — deliberately unbounded; a bound would permit a synchronous approval of an unknown path |

C1, C10 and C12 are the same scope from the
same side. C2 is phrased from the other side
and is not the same fact: it names where the
undeclared default applies (operations within
the composition that carry no explicit tier),
not which paths are outside the criterion.
C13 says what the digest is over. C4 forbids
the bound.

C2, C13 and C4 are left uncollapsed.

C12's restatement that C2's default is an
assignment in force — and that the default
applies inside the composition, not outside —
is C2's sub-case used as C12's assignment
clause. Left with C2.

## Whether 43 turned up a fifth

No. 43 introduced `governed set` under C12 /
C10 / C1. It placed C2 under `undeclared
default`, not under that concept. C13 was
not yet admitted; 47's sentence is not a
fifth copy of the scope paragraph.

`governed-set` in `spec/README.md`, a named
section before Response contracts. A
definition, not a criterion.

C2, C4 and C13 do not.

## Part 3 — blast radius

The definition site lists what references
it: C1, C10, C12. A change to this
definition is a change to every criterion
that references it.

## The observation this pass earns

Third instance of one fact in several
places (compat table, PRD, four scope
copies). Duplication is never a mistake at
the moment it is made. Worth asking what
else is stated more than once — by
counting, not waiting.

Three of the four copies were the same
sentence. The fourth was not. Comparison
before collapse is what kept C2.
