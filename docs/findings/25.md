## Part 0 — 24's qualifier

**Even with a backend contract, namespacing would hand the backend
an agent-chosen suffix plus a partition; we have chosen not to add
that contract.** A mechanism therefore exists at Level 2. The
guard sentence drafted in 24 does not license level-scoping. C7 is
unmet at Level 2 *by choice*.

The other sentence — "even with a backend contract there is nothing
to hand it" — is false. The backend does not need the gateway to
hash the body. It needs a stable identifier. The agent can supply a
retry-stable suffix; ctier can partition it under an unforgeable
subject. That is a backend contract (honour the partition, not the
suffix alone) and a 14a tension. Declining it is a choice, not an
impossibility.

The pending `headers.md` MUST should be scoped to the mechanism a
deployment states it relies on, not to a level. The
level-dependence question does not survive Part 0.

## Part 1 — classification

**C1 — Classification precedes routing.**
> No governed operation reaches its target before a decision is
> recorded.

**Mechanism.** "Recorded" is an artefact (a ledger write). The
property is: no governed operation is routed without having been
classified. Test **1**: a compiled Level 2 execute classifies at
deploy time and routes; Kong's `record_decision` is fail-open and,
without custody, writes nothing. The intent holds; the letter
describes a request-time write C10 already stopped requiring. Test
**3** as well: without a record sink the letter is unsatisfiable,
the property is not.

**C2 — Undeclared fails closed.**
> An operation reachable within a granted scope but carrying no
> `x-ctier-*` declaration is treated as Tier 4.

**Property.** Absence is the most severe outcome. "Tier 4" is the
model's name for that ceiling, not a replaceable component. Spec
`README.md` and `validation.md` cite it the same way. No test
failed.

**C3 — Escalation is unidirectional.**
> No runtime input may produce a tier lower than the declared tier,
> and no escalation stage may produce a tier lower than the tier
> entering that stage.

**Property.** Tiers do not go down. `validation.md` restates it as
a semantic rule on `x-ctier-escalate-to`. No test failed.

**C4 — The human is never in the request path.**
> No decision path blocks on human input. The enforcement point
> must not hold a connection open pending a human decision.

**Property.** Occupancy is the outcome. The connection sentence is
how occupancy appears on HTTP, not a named component. C5's
`pollUrl` prohibition is this property's dual, already stated
elsewhere. No test failed.

**C5 — The withheld response is terminal and non-retryable.**
> Status `202`, outside conventionally retried classes. No
> `Retry-After`. `retryable: false`. A machine-readable
> `agentAction`… The policy service constructs the complete
> response body. The enforcement point relays it unchanged…

**Mixed.** The title is a property. The body prescribes a status,
a field list, and a constructor. Protected property: a withheld
agent does not retry and does not stay engaged. Test **2**: `202`
and "the policy service constructs" can be replaced without
changing that outcome (another non-retryable status; a compiled
body). Test **1** does not currently fire: Level 3 withheld is
`202` from custody; Level 2 Tier 3 is a provisioning refusal, not
a withhold.

**C6 — Execution is from persisted context.**
> On approval, the operation executed is byte-identical to the
> operation described in the approval event in **method, request
> target, query and body**. The agent does not resubmit and is not
> involved.

**Mixed.** The outcome is: what executes is what was approved; the
agent is not the client. "Persisted context" names a store. Test
**2**: a signed snapshot the agent never resubmits would satisfy
the outcome without that store. Test **3**: without some retained
description of the operation, the letter is unsatisfiable. No
current target satisfies the intent while failing the letter:
custody execute is the letter.

**C8 — Expiry and rejection differ.**
> Rejection pauses the agent for the operation class. Expiry
> refuses the single operation and leaves the agent working. The
> effect of a rejection is **observed, not announced**.

**Property.** Two dispositions, two effects; the pause is state,
not a message. The rejection branch is unexercised (authorisation
layer). That is a gap in evidence, not a mechanism defect. No
test failed.

**C9 — Tier 4 has no resume path.**
> No state transition exists by which a Tier 4 operation executes
> under the agent's identity. Status `423`, `AgentSuspended`.
> Carries `incidentId`, `autoResume: false`, and
> `agentAction: halt_and_hand_off`. No correlation identifier.

**Mixed.** The first sentence is a property. The rest names a
status and a field list. Protected property: the agent has no
path by which a Tier 4 operation executes as the agent. Test
**2**: `423` can be replaced. Test **1** does not currently fire:
Kong and APISIX return `423`.

**C11 — An injected tier is trusted only from inside the trust
boundary.**
> A tier arriving as an inbound client header MUST NOT be honoured.
> The enforcement point MUST strip any client-supplied tier at the
> edge before setting its own, or the value MUST be
> integrity-protected…

**Mixed.** The honour-rule is a property: the agent does not
choose its tier. Strip-or-MAC names two mechanisms; `headers.md`
already keeps C11 as classification-ignores-injection, not plugin
order. Test **2**: strip and MAC are named as interchangeable.
Test **1** does not currently fire for the honour-rule: an injected
`x-ctier-tier: 1` on a compiled Tier 4 is `423` (08c, 17). 16a
found a different letter/intent split (read-before-strip) and
refused to fold it into C11.

**C12 — Tier assignment is bound to the deployed interface
revision.**
> The declared tier MUST travel with the gateway configuration
> rather than being resolved from a separately loaded document at
> request time, so that a deployed operation cannot exist without
> its governance assignment.

**Mechanism.** "Travel with the gateway configuration" is where
the assignment lives. The property, in the purpose clause: a
reachable operation cannot exist without the assignment composed
for it. Test **1**: a sidecar that loads a digest-pinned document
at request time (C13's binding, C10's second idiom) would satisfy
the intent and fail the letter. Test **2**: baked config and a
pinned fetch are interchangeable for the property. No current
target does the fetch.

## Part 3 — rank

1. **C1 — urgent.** Level 2 execute and Kong's fail-open ledger
   satisfy C10 (decision compiled; record MAY be asynchronous;
   sink-down is a named window) and fail C1's "recorded before it
   reaches its target." A conformant compiled implementation looks
   non-conformant, or someone will add a request-time write to
   match wording C10 already abandoned. Restate in the same pass
   shape as 11a: the decision precedes the route; the record is
   evidence.
2. **C12 — not urgent, next after C1.** No current target loads a
   spec at request time. The letter would exclude C10's second
   idiom the moment someone builds it. Restate before that target,
   not after.
3. **C5 — wait.** Mixed constructor and status. Level 3 matches
   the letter. Do not bulk-loosen `202` without asking what a
   different status newly permits.
4. **C9 — wait.** Same shape as C5: property plus a status. Live
   `423` matches.
5. **C6 — wait.** Custody execute is the letter. A restatement
   that dropped "persisted" would need a clause that the agent
   still cannot be the execute client and the bytes still cannot
   be reconstructed from a later submission.
6. **C11 — wait, and do not merge with requirement 3.** The
   honour-rule holds on the compiled targets. Strip-before-read
   already lives in `headers.md`. 16a declined to expand C11;
   this audit does not reverse that.
7. **C2, C3, C4, C8 — no restatement.** Properties. C8's rejection
   branch remains unexercised.

## The method question

Of the ten, **two are mechanisms** (C1, C12), **four are mixed**
(C5, C6, C9, C11), **four are properties** (C2, C3, C4, C8).

Asking found more than none. It did not find a universal drafting
failure. The two mechanisms are not the same residue: C1 is the
policy-service-era "recorded" that 11a left behind in a neighbour
criterion; C12 is the compiled architecture written as a location
rather than as a binding. The four mixed criteria state an
outcome and then nail a status, a store, or a constructor — the
C5 shape 09a already described.

So: run the ask-pass on anything that still names an artefact.
Do not re-read every sentence written before the architecture
pivoted as if it were automatically a mechanism. Half of these
ten were already properties. The expensive six were concentrated,
but not solely, in criteria written around a policy service;
C12 is the counterexample.

A method claim with a number: **two mechanisms and four mixed out
of ten**, found at the desk. C7 was the seventh artefact of the
original six-plus-this-audit if C1 is counted as leftover of C10
rather than a new class.
