# 30 — the ladder, without a capability that never existed

Spec **1.10.0**. Requires 28 and 29. Independent of 27.

## Spans first

Level 1 on the adoption ladder said *tier on spans, enforcing
nothing*. The reference has never stamped a span. There is no
tracing integration in the engine. Task 29 removed the claim from
engine documentation. The public specification, the one with the
DOI, still asserted it until this release.

A rung described in terms of a thing that does not exist is worse
than a rung described modestly. 1.10.0 says what Level 1 actually
does: classify and emit a decision record, enforce nothing. It
says, as an exclusion, that the reference does not stamp spans.

## The other four entries

**Level 2's Tier 3** is a provisioning refusal, not a withhold.
The row "Enforce 1/2/4" already implied that; the exclusion is now
written. Withhold is Level 3.

**The join key** is no longer an exclusion. 26 found it emitted
with nothing to join, because Level 2 wrote no decision record. 29
gave Kong and APISIX a schema-valid `[ctier-decision]` log line.
The key joins that. Apigee's generated `print()` is the Debug/Trace
session (`stepExecution-stdout`), not Cloud Logging. That is the
same standing as everything else Apigee: artefact-only.

**Level 4** accumulation is target-dependent. The reference builds
the scope-floor poller on Kong. It does not on APISIX. A spec
ladder that says the rung "gives" decomposition defence overclaims
relative to that target. Named.

**The fourth deployment requirement**, in 16d's exclusion form:
ctier does not guarantee durability of gateway-log decision
records. An operator who has not configured a durable collector for
`[ctier-decision]` lines has not recorded them. Custody remains the
durable ledger. The requirement does not apply to records written
there.
