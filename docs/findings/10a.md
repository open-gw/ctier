# 10a — no agent-facing response carries a URL

1.1.7 forbade a polling affordance on the withheld `202`. Task 10 found
the same gap one tier up: C9's letter does not forbid a handoff URL on
the `423`. Patching C9 alone would leave the next disposition to be
discovered the same way. The rule is now written once.

## How many places would have permitted a URL

Five, before this rule. None of them had already produced an artefact
that contained one.

1. **The `423`.** Named in the spec as a body (`incidentId`,
   `autoResume`, `agentAction`). No sentence forbade a location. This is
   the one task 10 pointed at, and it is the sharper case: a URL here
   makes the agent the mediator of a handover it was excluded from.
2. **The `403` excluded refusal.** A status and a description. No body
   contract at all, so nothing to forbid a field.
3. **C5 after 1.1.7.** Forbade a polling URL, a callback URL, and a
   status endpoint on the `202`. It did not forbid a handoff location or
   a documentation link that resolves to one of those. The occupancy
   argument covered watching the pending operation, not watching the
   human.
4. **`userMessage`.** An unconstrained string on both the `202` and the
   `423`. A URL in the prose would not have been a `pollUrl` property
   and would not have violated C5's letter.
5. **The example schemas.** `PendingAuthorization` and `AgentSuspended`
   declare properties and do not set `additionalProperties: false`.
   OpenAPI 3.1 defaults that to true, so `pollUrl` would still validate
   as an extra field. 1.1.7 removed it from the listed properties; it
   did not close the object.

C8's "no notification, callback or status affordance" is about not
creating a second message after the `202`. It is not a rule about
fields on the response the agent already received.

## Did any artefact contain one

No. The reference document's `userMessage` examples are sentences
without a location. Neither schema lists `pollUrl`, `callbackUrl`,
`Location`, or a handoff URI. The `servers` URL and the OAuth
`tokenUrl` are the API's own, not fields of an agent-facing
disposition.

The omission had produced a permission, not an instance. That is the
better outcome, and the reason to write the rule before task 11 writes
the remaining responses.

No schema changed. Closing `additionalProperties` on the example
objects would be a shape change; the MUST is behavioural and lives in
`validation.md`, where a second implementer will read it whether or not
they copy the example.
