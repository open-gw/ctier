# 36 — three corrections, one of them overdue

Spec **1.11.0**. Independent of 35. 27 does not block.

Three items had accumulated against the specification from
engine-side findings. Two were one-liners. The third has been
open since 14a.

## Level 4 is no longer target-dependent

1.10.0 recorded accumulation as available on Kong and not APISIX.
Task 32 built the APISIX poller; both live targets accumulate.

The qualification was replaced, not deleted. What still differs,
in 16d's exclusion form:

- How the timer starts (Kong plugin worker module; APISIX
  generated Lua with a pid-keyed shared-dict claim).
- Where the dictionary is declared (Kong compose; APISIX node
  config, not the generated route deck). An omitted dict is no
  escalation, not a refuse.
- Memory-pressure behaviour of that dictionary has never been
  observed.
- Apigee remains artefact-only for this rung.

"Both targets support Level 4" with nothing beside it is the
positively-stated claim 16d exists to prevent.

## The escalation window is Derived

`spec/conformance.md` described the 1000 ms window as measured.
It is not. It follows from the configured poll interval, which
makes it Derived under the taxonomy task 33 established in the
engine. The bound is threshold-crossing plus one poll interval.
Task 32's 216 ms sample is Observed and does not stand in for
that bound.

**Recommended, not written here.** An implementation that states
figures without saying which kind they are — Configured, Derived,
or Observed — is a defect the specification could prevent. The
taxonomy currently lives only in the engine
(`ctier-engine` `engine/docs/measurements.md`). Putting it in the
specification is an addition, not a correction. It belongs on a
later pass.

## Custody's execute path, in the threat model

Open since 14a. Task 17's Check 1 established it: when custody
executes from persisted context on approval, it calls the backend
directly. It does not traverse the enforcement point. Headers.md
already exempted the strip. Deployment requirement 2 already
named the bypass. Neither stated what an attacker gains.

The threat model now does. The last clause is the one a threat
model is for: compromise of custody yields direct backend access
under the policy service's own identity.

The custody path was discovered on 9 September by a task that was
checking something else, recorded correctly in two findings files,
referenced in a deployment requirement, and never written into the
threat model. It survived three spec versions that way.

A finding recorded in the place it was found is not the same as a
finding published where a reader would look, and this project now
has a habit of the first that partly substitutes for the second.
