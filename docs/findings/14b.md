# 14b — the boundary contract, and what ctier does not enforce

Spec **1.5.0**. Inventory re-derived from `ctier-engine` after 14a
and 14a.1, not copied from `docs/findings/14.md`.

## Answers

**Stop condition.** No emitted header carries a token, an approver
identity, or a decision a backend could take as permission. 14a
removed `x-ctier-approver` and `x-ctier-agent`. The remaining
upstream names are provenance (`x-ctier-tier`, `x-ctier-deployment`,
`x-ctier-operation`, dual-emit `x-ctier-composition`,
`x-ctier-correlation-id`). `Idempotency-Key` is C7.
`Authorization` on execute is the policy service as itself.

**Emit versus strip.** Kong: emit ⊆ prefix strip. Apigee: no
`x-ctier-*` HTTP emit upstream; closed strip. APISIX: the three
emitted names are not in `proxy-rewrite` remove (A2: remove-and-set
of the same name drops the set); they are overwritten. Custody
execute is exempt: it constructs from persisted context. Closed
strips (Apigee, APISIX) omit `x-ctier-correlation-id`, so an agent
can inject a join key on the forwarding path. Spec requires closed
strips to include provenance names they do not set. Engine follow-on,
not a hard stop: the path that emits correlation-id does not go
through those strips.

**`x-ctier-correlation-id` on both paths?** Custody execute: **yes**.
Enforcement path: **no.** 14a's recovery (correlation id → decision
record → agent and approver) holds for approved execute. It has
nothing to join on Tier 1 / Tier 2; those calls have no pending
context. That is not a hole in 14a. It is a hole if a reader thought
every backend request carried the join key.

**Part 4.** The gap is worth closing. The corpus can agree on
disposition and still forward a forged header. A new case shape
(observe what the backend received) is a review decision. Not taken
here.
