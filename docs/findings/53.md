# 53 — Additive evolution is two rules

Spec **1.22.0**. Requires 51.
Independent of the engine, and of
engine 52. Engine behaviour was
not changed. C11 is unaltered.
CITATION.cff remains 0.1.0.

51 scoped Additive evolution to
unknown `x-ctier-*` headers at
the trust boundary. The word
stayed ignore. Nobody asked the
permit-question: scoping felt
like it cannot loosen. A scope
is also a placement. The rule
was document evolution. Placed
at the trust boundary it became
permission to forward an
attacker-chosen header.

---

## Part 0 — what the strip matches

Recorded before the wording
moved.

Kong `strip_inbound` in
`targets/kong/plugin/handler.lua`
walks every inbound header.
`PREFIX` is `x-ctier-`. A name
whose lowercased prefix is that
string is cleared, plus the
named aliases. An unknown
`x-ctier-foo` matches. A closed
list of known members would
not.

APISIX `_lua_strip_namespace`
in `engine/ctier/generate.py`
does the same prefix test.
`proxy-rewrite` remove is
aliases only (A2). The Lua
function is the namespace
walk. An unknown `x-ctier-foo`
matches there too.

The reference boundary suite
already sends `x-ctier-foo` and
`x-ctier-unknown-audit` and
asserts them absent at the
backend, on both live engines.

Whole namespace, both engines.
Not known-members-only. An
unknown `x-ctier-*` header does
not reach the backend today.
The hole is in the wording —
51's ignore — not in the
running strip. No engine fix.

## Part 1 — two names

**Additive evolution.** Reader
of a document. Consumers MUST
ignore fields they do not
recognise, in a named
extensions object where a
document type defines one.
Not a criterion. Settled.

**C16 — The namespace is
stripped on ingress.**
Enforcement point at the
trust boundary. Unknown
`x-ctier-*` headers. Own
name.

They must not share a name.
A reader-of-documents rule
and an enforcement-point
rule are not the same
requirement. Same principle
as deployment requirement 5:
enforced versus cannot-enforce
must not share a name.

---

## Part 2 — one action

The request half states
**strip**. The mechanism is
the one C11 already names
for an injected tier. This
rule does not restate it.
C11 is unaltered.

Ignore is not this rule.
Ignore plus a note that
stripping is also acceptable
is not this rule. An
implementation that ignores
an unknown `x-ctier-*`
header and forwards it does
not satisfy. C11's never-read
still satisfies C11. It does
not satisfy this rule if the
header still reaches the
backend.

---

## Part 3 — the permit-question

39 asks what loosening newly
permits. 51 did not ask.
Scoping felt like it cannot
loosen. Wrong when the scope
lands where the rule was
never written.

Additive evolution was
document evolution: a new
field does not fail the
reader. Scoped to the trust
boundary, ignore newly
permits forwarding a header
the agent chose. That is
the hole. Recorded.

The request half does not
permit it. The action is
strip. Loosening strip
without a further clause
would permit
forward-without-strip —
the hole 39 already named
and left in `headers.md`.
This pass consumes that
candidate.

## Admission

Applied to the request half
alone.

A second implementation must
strip the entire `x-ctier-*`
namespace on ingress.
Testable against a running
deployment. Not a document
rule. Not a deployment
condition the implementation
cannot make unavoidable.

Admitted. C16. The heading
in `headers.md` gains the
letter. The MUST there is
unaltered. Declared evidence
is none.

Additive evolution does
not meet the rule. It is
still a named validation
rule about the reader of
a document.

## A scope is also a placement

Asked of C1, C2, C10, C12
and `governed-set`. Not
rewritten here.

**C12.** 1.14.0 scoped
"reachable" to the composed
description. The title still
says reachable. The miss —
a path at the enforcement
point but absent from the
composition — was placed
outside the criterion. Words
of the title unchanged. The
threat left the letter.
Already a named gap: Kong
assigns Tier 4 via a global
plugin; APISIX does nothing.
A narrowing that was also a
placement.

**C1.** 1.15.0 used the same

**C10.** Coverage scoped to
the `governed-set`. 1.19.0

caught the placement risk
on the sink half. The
coverage narrowing remains.

**C2.** The undeclared
default's subject —
operations in the
composition that carry no

criterion boundary. 44

onto a new threat surface.

**`governed-set`.** A
definition site. A change
to it is a change to C1,
C10 and C12. Blast radius
44 named. Not itself a
threat-model change.

never been written.

permit-question, measured
on a narrowing.
